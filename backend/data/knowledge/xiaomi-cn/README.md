# 小米国行手机本地知识资料

资料落盘日期：2026-10-22。范围：中国大陆小米手机。

日常修改和入库只维护 **`原始资料/` 下的 Markdown**。这些文件基于官方页面文字正文，补充了入库元数据、章节标题和明确标出的本地适用边界。`整理稿/` 是旧 JSONL 的历史可读版本，不参加本次入库；不要修改整理稿后期待线上答案变化。来源和采集时的快照哈希保留用于追溯，不在聊天界面展示。

## 一条命令同步

从项目根目录、使用安装了后端依赖的 Python 环境执行：

```bash
python -m backend.scripts.rebuild_knowledge
```

也可以在 IDE 直接运行 `backend/scripts/rebuild_knowledge.py`，会定位到同一份项目配置和源目录。

只检查 Markdown 格式、切块和 FAQ 引用，不写数据库：

```bash
python -m backend.scripts.rebuild_knowledge --dry-run
```

流程：读取本地 Markdown → 校验元数据及章节引用 → 按标题和段落切块 → BGE-M3 编码 → 更新 Milvus 与 Redis → 同步 FAQ → 核对新索引 → 清理过期小米手机索引 → 更新型号目录。脚本不访问官网，不调用 LLM，不要求手工编辑 JSONL 或版本号。

### 修改方法

1. 修改下方 `原始资料/` 中对应文件的正文，保存后执行同步命令。
2. 文件顶部 YAML 的 `knowledge_id` 是稳定文件标识；`product_models` 指定适用型号，`general_model` 指定通用政策入口。
3. `faqs` 的 `questions` 是常见问法，`sections` 引用本文件的正文标题。FAQ 答案每次从这些章节重新生成，与文档 RAG 使用同一正文；修改被引用的标题时，也要修改 `sections`。
4. 文件内容变化会自动生成 `md-...` 版本。顶部 `capture_sha256`、`body_sha256` 记录的是最初采集快照，不是需要手工更新的运行版本。
5. 删除某个章节、问法或文件后重新运行，对应的旧向量会清理。整个源目录为空、ID 重复或 FAQ 引用了不存在的章节时，脚本在写库前停止，避免误清空资料。

只需要运行同一条同步命令，无需重启聊天服务。检索使用强一致性读取更新后的索引；Milvus 保存向量、文档 ID 和版本，Redis 保存该版本的正文，二者会一起更新。

同步仅替换这套小米手机资料，包括第一次运行时替换原 JSONL 生成的旧小米手机索引；保留 GC 演示资料、其他品类 FAQ 和 v1 旧库。旧版本 Redis 正文保留作追溯，不再由当前索引或 FAQ 版本指针引用。入库中途失败时不主动清空整个索引，修复问题后重新执行；这不是跨 Milvus/Redis 的原子事务，运行期间可能暂时读到新旧混合内容，不要并行运行多个同步进程。
