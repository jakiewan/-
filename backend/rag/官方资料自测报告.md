# 小米官方资料 RAG 自测报告

日期：2026-10-22。范围：`feature/fixed-rag` 的固定知识检索流程。

## 结果

覆盖50项场景（含多轮），按修复后的最终记录逐项复核通过。失败项及受影响问法做了定向复测；关键词初筛只用于发现问题，最终检查回答主题、参数、适用范围、引用和结束事件。此结果不是所有问法的准确率保证。

- 36条国行参数：小米14、小米15、小米15 Pro、小米15 Ultra。
- 10项政策FAQ、31个问法；政策按通用和型号范围建立50条索引引用，合计86条官方文档。
- 当前独立文档索引336条，包含原有演示资料；独立FAQ索引95个问法，其中31个为官方手机问法。
- 86条官方文档逐项核对ID、版本、正文及元数据；官方手机FAQ排除了原模拟条款，旧FAQ与v1文档保留。
- Python检查、前端构建、原有5项Playwright浏览器回归通过。未新增仓库测试框架。

## 主要修复

1. FAQ向量相似度误把容量、屏幕、充电问题当成维修价格：复用Reranker校验候选，先精排问法再按FAQ条目去重；泛品类政策不作为型号参数答案。
2. 语义候选不明确时继续文档RAG，读取完整条款；缺少实际必要条件仍澄清，服务异常明确失败。
3. 型号在政策问题中漏抽、多轮品类丢失：从可信目录恢复明确型号及品类，纠正型号时覆盖旧对象，换话题隔离旧条件。
4. 型号比较：检索两边资料、分别保留相关证据，输出有据参数表，缺项标未核实，不根据资料缺项推断功能多少或优劣。
5. 国行、海外、其他品牌与GC模拟资料隔离；不将小米政策套给苹果，也不把否定苹果的正常小米问题误拒绝。
6. 主机、附件与内置电池期限分开；旧附件条款不直接当作现代机型内置电池期限。
7. 质量退换修政策询问补充了咨询入口示例；未修改售后执行逻辑。
8. 回复引用直接指向官方网页，并保留内部证据ID。

主流程仍为：问题重写 → FAQ优先 → 原查询/HyDE两组dense+sparse召回 → RRF → 精排 → 基于证据生成。没有新增Agent规划或重查循环。
